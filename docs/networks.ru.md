# Сетевые схемы: одна подсеть, разные подсети, несколько адресов

*English version: [networks.md](networks.md)*

filedrop **не** предполагает, как устроена ваша сеть. В одном кабинете — и вообще на одной площадке — ноутбук и панель могут быть:

| Схема | Пример | Что происходит |
|---|---|---|
| **одна подсеть** | ноутбук `192.168.10.15/24`, панель `192.168.10.40/24` | ноутбук обращается к панели напрямую |
| **разные подсети** (через маршрутизатор) | ноутбук `172.26.1.86/16`, панель `10.173.42.104/16` | трафик идёт через маршрутизатор; между подсетями должен быть открыт TCP 22 |
| **несколько адресов** | ноутбук и по кабелю, *и* по Wi-Fi; у панели вторая сетевая | предпочитается адрес из общей подсети |
| **вперемешку на одной площадке** | в одних кабинетах одна подсеть, в других две | каждая пара оценивается отдельно — настроек «по кабинетам» или «по подсетям» нет |

Один и тот же `agent.conf` подходит для всех схем.

## Как агент принимает решение

1. **Каждый агент сообщает справочнику все свои пригодные IPv4-адреса с масками подсетей** раз в `REGISTER_INTERVAL_SEC` секунд (`192.168.10.15/24`, …). Loopback, link-local и мосты контейнеров/ВМ (`docker0`, `br-*`, `veth*`, `virbr*` … см. `IGNORE_INTERFACES`) исключаются: у многих машин они с одинаковыми адресами и выглядели бы как «общая подсеть». Справочник также запоминает адрес, с которого пришёл запрос.
2. **Чтобы отправить, ноутбук спрашивает справочник про панель** и получает **все** адреса панели.
3. **Он ранжирует их**: сначала адреса из одной из собственных подсетей ноутбука («та же подсеть»), потом остальные («через маршрутизацию»). Собственные адреса не используются никогда.
4. **Подключается к первому адресу, у которого отвечает SSH-порт** (проверка 3 с), и отправляет. Если не отвечает ни один, объект остаётся в общей папке, а попытка повторяется каждые несколько секунд; в журнале видно, какие адреса не подошли.

То же ранжирование применяется к ответам DNS (режим `dns`: все A-записи) и статической таблицы (режим `static`: несколько адресов в строке), поэтому поведение не зависит от способа определения адреса.

Справочник — «телефонная книга» с хорошей памятью на адреса; самих файлов он не видит.

## Как проверить

На ноутбуке:

```sh
filedrop-agent check
```

```
[OK  ] hostname pc-room12 -> role "pc", this machine is a client
      this machine's usable addresses: [172.26.1.86/16]
      counterpart candidates: [panel-room12]
[OK  ] panel-room12 resolves to [10.173.42.104] (directory mode)
[OK  ] 10.173.42.104 (other subnet, routed): port 22 is reachable
```

Пометка `same subnet` / `other subnet, routed` показывает, какая из схем выше у этой пары. На странице состояния справочника (`http://HOST:8781/status`, с заголовком токена) для каждой машины видно, с какого адреса она подключилась и какие адреса сообщила.

## Настройка справочника под это

Сервер справочника может стоять в одной подсети или иметь адрес в каждой (несколько сетевых карт или одна машина в нескольких VLAN). Укажите **все** его адреса в `DIRECTORY_URL` на **всех** машинах:

```
DIRECTORY_URL=http://10.0.0.5:8781, http://172.16.0.5:8781
```

Агент пробует их по очереди с коротким таймаутом, затем «прилипает» к сработавшему, так что одна и та же строка годится в любой подсети. (Если первый адрес оказался недоступным, один раз появится заметка в журнале — это безвредно, при желании переставьте адреса.) Откройте TCP 8781 в файрволе сервера из каждой подсети, где есть машины.

## Файрволы и маршрутизация между подсетями

Когда ноутбук и панель в разных подсетях, маршрутизатор/файрвол между ними должен пропускать **TCP 22 из подсети ноутбука в подсеть панели** (ответы подразумеваются). Панель сама к ноутбуку никогда не подключается. В режимах `dns` и `directory` команда `check` сразу покажет, что порт закрыт.

## Типичные ситуации

- **«В этом кабинете обе машины в одной подсети, в соседнем — нет».** Ничего делать не нужно. Конфигурация в обоих кабинетах одинакова.
- **Ноутбук перешёл с кабеля на Wi-Fi.** Следующая регистрация (≤ 45 с) обновит адреса; перезапуск не нужен.
- **Справочник показывает у машины «не тот» адрес** (например, адрес маршрутизатора из-за NAT между машиной и справочником). В сообщённых адресах всё равно есть настоящие, а проверка порта выберет тот, что отвечает.
- **Справочника нет вообще.** Режим `dns` с несколькими A-записями или `static` с несколькими адресами в строке работает так же.
