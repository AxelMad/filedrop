# Справочник по настройке

*English version: [configuration.md](configuration.md)*

Агент читает `/etc/filedrop/agent.conf` (другой файл — флаг `-config FILE`): простые строки `KEY=VALUE`, `#` — комментарий, значение можно взять в кавычки. Неизвестный параметр — ошибка (чтобы опечатки не проходили незамеченными). После правки: `sudo systemctl restart filedrop-agent`, затем `filedrop-agent check`.

## 1. Схема имён (кто панель, кто ноутбук)

filedrop связывает машины **только по hostname**:

- `HOSTNAME_PATTERN` — регулярное выражение ([синтаксис Go/RE2](https://github.com/google/re2/wiki/Syntax)); оно должно совпасть с *целым* hostname и содержать именованную группу `(?P<role>…)`.
- `PANEL_ROLES` — значения этой группы, означающие «панель» (приёмник); `CLIENT_ROLES` — «клиент» (отправитель). Через запятую или пробел. Одно значение не может быть в обоих списках.
- **Пара** машины — её собственный hostname, у которого *заменена только часть role* на роль противоположного вида. Всё остальное в имени (площадка, кабинет, номер …) у пары должно совпадать. Панель с несколькими ролями клиентов пробует каждую по очереди (удобно, когда в кабинете либо ноутбук, либо моноблок).

| Шаблон | Роли | `pc-room12` общается с |
|---|---|---|
| `^(?P<role>panel\|pc)-(?P<site>.+)$` (по умолчанию) | панель=`panel`, клиент=`pc` | `panel-room12` |
| `^(?P<site>[a-z]+)-(?P<role>board\|desk)-(?P<n>\d+)$` | панель=`board`, клиент=`desk` | `north-desk-7` ⇄ `north-board-7` |
| `^(?P<role>[pnm])[0-9]{4}-(?P<s>\d+)-(?P<r>\d+)-(?P<n>\d+)$` | панель=`p`, клиент=`n m` | панель `p1234-0-421-0` ⇄ `n1234-0-421-0` или `m1234-0-421-0` |

Имена вообще без схемы: `ROLE=client` (или `panel`) и пара в `PEER_HOSTNAMES` (имена или IP-адреса). `PEER_HOSTNAMES` в любом случае перекрывает вычисленную пару.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `ROLE` | `auto` | `auto` — по hostname; `panel` / `client` — принудительно |
| `HOSTNAME_PATTERN` | `^(?P<role>panel\|pc)-(?P<site>.+)$` | см. выше |
| `PANEL_ROLES` | `panel` | |
| `CLIENT_ROLES` | `pc` | |
| `PEER_HOSTNAMES` | *(пусто)* | явная пара |

## 2. Как найти IP пары (`RESOLVE_MODE`)

| Режим | Когда | Что нужно |
|---|---|---|
| `dns` (по умолчанию) | имена резолвятся: DNS, mDNS/avahi, `/etc/hosts` | ничего |
| `directory` | DHCP, имён в DNS **нет** | служба `filedrop-directory` ([установка](#служба-справочника)) |
| `static` | фиксированные адреса (резервации DHCP) | файл-таблица |

**directory** — каждый агент раз в `REGISTER_INTERVAL_SEC` секунд регистрируется со **всеми своими локальными адресами**; сервер также запоминает IP, с которого пришёл запрос. Пара получает их все и выбирает адрес из своей подсети — см. [networks.ru.md](networks.ru.md).

- `DIRECTORY_URL` — один URL или **все** адреса сервера через запятую/пробел (например, по адресу на подсеть). Одна и та же строка подходит для всех машин: агент пробует адреса по очереди и «прилипает» к тому, который работает из его подсети (если первый не подошёл, один раз появится заметка в журнале).
- `DIRECTORY_TOKEN` — общий секрет (заголовок `X-Filedrop-Token`), его печатает установщик справочника.

**static** — `STATIC_HOSTS_FILE` (по умолчанию `/etc/filedrop/hosts.tsv`): строки `hostname<пробел/tab>ip [ip …]` (адресов может быть несколько); файл перечитывается при каждом поиске, правки применяются без перезапуска.

### Служба справочника

Нужна только для `RESOLVE_MODE=directory`. Скачайте из релиза `filedrop-directory-<версия>-linux-<arch>.tar.gz`, распакуйте на постоянно включённой Linux-машине, выполните `sudo ./install.sh` (он напечатает токен) и откройте TCP 8781 в её файрволе. Страница состояния: `curl -H "X-Filedrop-Token: …" http://HOST:8781/status`. К самим файлам справочник не прикасается — это просто «телефонная книга».

## 3. Папки и ярлык

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `INBOX_DIR` | `/opt/filedrop/inbox` | панель: куда попадает принятое |
| `OUTBOX_DIR` | `/opt/filedrop/outbox` | клиент: «Общая папка», куда пользователи кладут файлы |
| `SENT_DIR` | `/opt/filedrop/outbox/.sent` | клиент: сюда переносится доставленное |
| `REMOTE_INBOX_PATH` | `/inbox` | путь к inbox **изнутри chroot sshd** (`ChrootDirectory /opt/filedrop`). Это не то же значение, что `INBOX_DIR`, хотя папка одна и та же |
| `SHARED_FOLDER_NAME` | `Shared folder` | имя ярлыка на рабочем столе (любой язык, например `Общая папка`) |

Если меняете `INBOX_DIR`/`OUTBOX_DIR`, согласованно меняйте `ChrootDirectory` в `/etc/ssh/sshd_config.d/filedrop.conf`, `REMOTE_INBOX_PATH` и пути в `filedrop-setup` — рекомендуются значения по умолчанию.

## 4. Передача

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `SSH_USER` | `filedrop` | учётка на принимающей стороне |
| `SSH_KEY` | `/etc/filedrop/id_ed25519` | приватный ключ |
| `SSH_PORT` | `22` | |
| `KNOWN_HOSTS_FILE` | `/var/lib/filedrop/known_hosts` | ключи хостов принимаются при первом контакте (`accept-new`), дальше закрепляются |
| `IGNORE_INTERFACES` | `lo docker* br-* veth* virbr* lxcbr* lxdbr* cni* flannel* cali* podman* vmnet* vboxnet*` | шаблоны интерфейсов, чьи адреса не сообщаются и не учитываются при оценке «та же подсеть» |
| `SCP_SFTP_FLAG` | `no` | добавить `scp -s` (принудительно протокол SFTP). Нужно клиентам с OpenSSH 8.7–8.9 |

## 5. Тайминги

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `POLL_INTERVAL_SEC` | `2` | как часто проверяется outbox |
| `SETTLE_CHECKS` | `2` | сколько опросов подряд размер не должен меняться, прежде чем отправлять (для папки — суммарный размер) |
| `REGISTER_INTERVAL_SEC` | `45` | режим directory: как часто агент регистрируется |
| `LOG_FILE` | *(пусто)* | пусто = журнал (`journalctl -u filedrop-agent`) |

Таймаут передачи: 60 с + размер ÷ 2 МБ/с, не более 20 минут.

## 6. Автоочистка (`/etc/filedrop/cleanup.conf`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `RETENTION_DAYS` | `14` | удалять старше N дней; предупреждения за 4 дня, за 1 день и в последний день |
| `NOTICE_LANG` | `auto` | `auto`, `en` или `ru` |

Возраст папки — возраст самого нового файла внутри. Очистка запускается при загрузке и раз в сутки (`systemctl list-timers | grep filedrop`).

## Вспомогательные команды

```sh
filedrop-agent check                     # полная диагностика машины
FILEDROP_HOSTNAME=pc-room12 filedrop-agent info    # проверить схему, не переименовывая машину
```
