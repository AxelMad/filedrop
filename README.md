# filedrop

**Drop a file or folder into the "Shared folder" on a teacher's laptop — it shows up on the interactive panel in the same room. No clicks, no USB sticks, no cloud.**

*Русская версия: [README.ru.md](README.ru.md)*

filedrop is a small Go agent (one static binary, no runtime dependencies) plus packaging for Linux classrooms. The same package goes onto every machine; each machine works out whether it is a **panel** (receives) or a **client** (a laptop / PC / all-in-one that sends) from its own hostname, finds its counterpart in the same room, and hands files over through SFTP with a dedicated, locked-down SSH key.

```
laptop  pc-room12                                  panel  panel-room12
Shared folder  (= /opt/filedrop/outbox)  ──scp/SFTP──▶  Shared folder  (= /opt/filedrop/inbox)
                         key confined to a chrooted, SFTP-only account
```

## Features

- Files **and whole folders**, large files included (the transfer timeout scales with the size; a file that is still being copied in is not sent until its size stops changing).
- **Zero configuration per machine**: the role and the counterpart are derived from the hostname by a configurable regular-expression scheme (`pc-room12` ⇄ `panel-room12` by default; any scheme works — see [docs/configuration.md](docs/configuration.md)).
- Three ways to find the counterpart's IP: **DNS/mDNS/hosts**, a tiny **directory service** for DHCP networks without DNS, or a **static table**.
- **Subnet-aware**: a laptop and its panel may be in the same subnet or in different ones, on one site or many, with one address or several (cable + Wi-Fi). Agents report all their addresses to the directory, take all of the counterpart's addresses back, prefer the one on their own subnet and only use an address whose SSH port really answers. No per-subnet configuration — see [docs/networks.md](docs/networks.md).
- **Safe by construction**: the receiving account is chrooted into an SFTP-only jail (no shell, no TTY, no forwarding), the key is generated by *you* at install time and never shipped in a package, the agent runs as an unprivileged systemd service with two capabilities and a read-only file system outside `/opt/filedrop`.
- A **desktop shortcut** with the same name on panel and laptop (self-healing, recreated if a user deletes it) and **auto-cleanup** with pop-up warnings (default: 14 days).
- Packages: **.deb**, **.rpm**, and a generic **.tar.gz** installer for **amd64** and **arm64**; statically linked, so they run on old distributions too.

## Requirements

- Linux with **systemd** and **OpenSSH** (`openssh-client` on every machine, `openssh-server` on panels). Clients need OpenSSH ≥ 9.0, or ≥ 8.7 with `SCP_SFTP_FLAG=yes` (the receiver speaks SFTP only).
- A laptop can reach its panel on TCP 22 — in the same subnet or across routed subnets (firewalls between subnets must allow it).
- Optional: `zenity` for the cleanup pop-ups.

## Quick start

**1. Create the fleet key once** (on your admin workstation; keep it private, never commit it):

```sh
filedrop-keygen ./filedrop-fleet-key     # installed with the package; from a clone: packaging/common/filedrop-keygen
# or by hand: ssh-keygen -t ed25519 -N '' -C filedrop-fleet -f fleet_key
```

**2. Install the package on every machine** (download from the [Releases](../../releases) page):

```sh
sudo apt install ./filedrop-agent_2.0.0_amd64.deb      # Debian / Ubuntu / Astra …
sudo rpm -i filedrop-agent-2.0.0-1.x86_64.rpm          # RHEL / ROSA / RED OS / ALT …
sudo ./install.sh                                       # generic tar.gz, any systemd distro
```

**3. Put the key on the machine and check:**

```sh
sudo filedrop-setup --key ./filedrop-fleet-key/fleet_key
filedrop-agent check
```

For many machines use the bulk script instead: `scripts/rollout.sh rollout.conf` (see [examples/rollout.conf.example](examples/rollout.conf.example)).

Name the machines to match the scheme (default `pc-<room>` and `panel-<room>`), or adapt `HOSTNAME_PATTERN` in `/etc/filedrop/agent.conf` to the names you already have. Then drop a file into **Shared folder** on the desktop of the laptop and it appears on the panel within seconds.

Just two machines and no fleet? Run `sudo filedrop-setup --generate-key` on the laptop and authorize the printed public key on the panel with `sudo filedrop-setup --authorize '<key>'`.

## Commands

| Command | What it does |
|---|---|
| `filedrop-agent` | the service itself (started by systemd) |
| `filedrop-agent check` | diagnoses this machine: role, folders, key, counterpart's IP and TCP reachability |
| `filedrop-agent info` | prints `role=`, `target=`, `link_name=` for scripts |
| `filedrop-setup` | (re)applies users, folders, permissions, services; `--key`, `--generate-key`, `--authorize` |
| `filedrop-keygen` | creates the fleet key pair |

## Upgrading from 1.x

Version 2.0 made the hostname scheme configurable and removed the school-specific defaults. Fleets that used the built-in `p/n/m<school>-<site>-<room>-<n>` names must add the three naming lines from [examples/structured-names/agent.conf](examples/structured-names/agent.conf) to `agent.conf` (and adjust the school number). The fleet key is no longer inside the package: install your existing key with `filedrop-setup --key`. See [CHANGELOG.md](CHANGELOG.md).

## Building from source

```sh
make test            # go vet-clean, unit tests
make packages        # dist/: .deb .rpm .tar.gz for amd64 + arm64, SHA256SUMS
```

Needs Go ≥ 1.22; `dpkg-deb` and `rpmbuild` are optional (the matching package type is skipped without them).
