# filedrop

**Положил файл или папку в «Общую папку» на ноутбуке учителя — он сразу появился на интерактивной панели в том же кабинете. Без кликов, флешек и облаков.**

*English version: [README.md](README.md)*

filedrop — небольшой агент на Go (один статический бинарник без зависимостей) и пакеты для Linux-классов. Один и тот же пакет ставится на все машины; каждая сама определяет по своему hostname, кто она — **панель** (принимает) или **клиент** (ноутбук / ПК / моноблок, отправляет), находит пару в своём кабинете и передаёт файлы по SFTP выделенным ограниченным SSH-ключом.

```
ноутбук  pc-room12                                   панель  panel-room12
Общая папка (= /opt/filedrop/outbox)  ──scp/SFTP──▶  Общая папка (= /opt/filedrop/inbox)
                         ключ ограничен SFTP-chroot, без shell
```

## Возможности

- Передаются **файлы и папки целиком**, в том числе большие (таймаут растёт вместе с размером; файл, который ещё копируется, не отправляется, пока его размер не перестанет меняться).
- **Ноль настроек на каждой машине**: роль и пара определяются по hostname по настраиваемой схеме на регулярных выражениях (по умолчанию `pc-room12` ⇄ `panel-room12`; подойдёт любая схема — см. [docs/configuration.ru.md](docs/configuration.ru.md)).
- Три способа найти IP пары: **DNS/mDNS/hosts**, лёгкий **справочник** для DHCP-сетей без DNS или **статическая таблица**.
- **Учёт подсетей**: ноутбук и панель могут быть в одной подсети или в разных, на одной площадке или на разных, с одним адресом или с несколькими (кабель + Wi-Fi). Агенты сообщают справочнику все свои адреса, получают все адреса пары, предпочитают адрес из своей подсети и используют только тот адрес, у которого SSH-порт реально отвечает. Настройки «под подсеть» не нужны — см. [docs/networks.ru.md](docs/networks.ru.md).
- **Безопасно по построению**: принимающая учётка заперта в SFTP-chroot (без shell, TTY и проброса портов), ключ создаёте **вы сами** при установке и он не лежит ни в одном пакете, агент работает как непривилегированная служба systemd с двумя capability и файловой системой «только чтение» вне `/opt/filedrop`.
- **Ярлык на рабочем столе** с одинаковым именем на панели и ноутбуке (сам восстанавливается, если пользователь его удалил) и **автоочистка** с всплывающими предупреждениями (по умолчанию 14 дней).
- Пакеты: **.deb**, **.rpm** и универсальный установщик **.tar.gz** для **amd64** и **arm64**; сборка статическая, работает и на старых дистрибутивах.

## Требования

- Linux с **systemd** и **OpenSSH** (`openssh-client` на всех машинах, `openssh-server` на панелях). Клиентам нужен OpenSSH ≥ 9.0 либо ≥ 8.7 с `SCP_SFTP_FLAG=yes` (приёмник понимает только SFTP).
- Ноутбук достаёт до своей панели по TCP 22 — в одной подсети или через маршрутизацию (файрволы между подсетями должны это разрешать).
- Необязательно: `zenity` для всплывающих окон автоочистки.

## Быстрый старт

**1. Один раз создайте ключ парка** (на рабочем месте администратора; храните в тайне, никогда не коммитьте):

```sh
filedrop-keygen ./filedrop-fleet-key     # ставится вместе с пакетом; из клона: packaging/common/filedrop-keygen
# или руками: ssh-keygen -t ed25519 -N '' -C filedrop-fleet -f fleet_key
```

**2. Установите пакет на каждую машину** (скачайте со страницы [Releases](../../releases)):

```sh
sudo apt install ./filedrop-agent_2.0.0_amd64.deb      # Debian / Ubuntu / Astra …
sudo rpm -i filedrop-agent-2.0.0-1.x86_64.rpm          # RHEL / РОСА / РЕД ОС / ALT …
sudo ./install.sh                                       # tar.gz, любой дистрибутив с systemd
```

**3. Положите ключ на машину и проверьте:**

```sh
sudo filedrop-setup --key ./filedrop-fleet-key/fleet_key
filedrop-agent check
```

Для многих машин — скрипт массовой раскатки: `scripts/rollout.sh rollout.conf` (см. [examples/rollout.conf.example](examples/rollout.conf.example)).

Назовите машины по схеме (по умолчанию `pc-<кабинет>` и `panel-<кабинет>`) или подстройте `HOSTNAME_PATTERN` в `/etc/filedrop/agent.conf` под уже существующие имена. Потом просто положите файл в **«Общую папку»** на рабочем столе ноутбука — через несколько секунд он на панели.

Всего две машины и нет парка? На ноутбуке выполните `sudo filedrop-setup --generate-key`, а напечатанный публичный ключ разрешите на панели: `sudo filedrop-setup --authorize '<ключ>'`.

## Команды

| Команда | Что делает |
|---|---|
| `filedrop-agent` | сама служба (запускает systemd) |
| `filedrop-agent check` | диагностика машины: роль, папки, ключ, IP пары и доступность по TCP |
| `filedrop-agent info` | печатает `role=`, `target=`, `link_name=` для скриптов |
| `filedrop-setup` | (пере)применяет пользователя, папки, права, службы; `--key`, `--generate-key`, `--authorize` |
| `filedrop-keygen` | создаёт пару ключей парка |

## Обновление с 1.x

В версии 2.0 схема hostname стала настраиваемой, а привязки к конкретной школе убраны. Парки, где использовались встроенные имена вида `p/n/m<школа>-<площадка>-<кабинет>-<номер>`, должны добавить в `agent.conf` три строки со схемой из [examples/structured-names/agent.conf](examples/structured-names/agent.conf) (с номером своей школы). Ключ парка больше не внутри пакета: установите существующий ключ командой `filedrop-setup --key`. Подробнее — в [CHANGELOG.md](CHANGELOG.md).

## Сборка из исходников

```sh
make test            # vet, юнит-тесты
make packages        # dist/: .deb .rpm .tar.gz для amd64 + arm64, SHA256SUMS
```

Нужен Go ≥ 1.22; `dpkg-deb` и `rpmbuild` необязательны (без них соответствующий тип пакета пропускается).
